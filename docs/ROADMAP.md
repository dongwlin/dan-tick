# dan-tick Roadmap

本文规划 dan-tick 的产品方向：按主题持续的改进方向、长期候选池和明确不做的事，**不为具体版本承诺范围或顺序**。功能范围及验收标准以 [PRD](PRD.md) 为准；执行项与实现状态见 [待办](待办.md)；技术决策以 [技术栈选型](技术栈选型.md) 为准。当前产物、发布流程与发布门槛见 [构建与发布](构建与发布.md)。

## 1. 计划方式

- **按主题推进，不按版本号切分范围。** 主题是可以长期累积的方向（如桌面常驻体验、日常使用完善），事项在主题内独立完成。
- **版本号只表示交付节点，不是开发阶段编号。** 达到 [PRD 验收标准](PRD.md#10-验收标准)、具备发布条件时才在准备发布的提交上创建正式 Tag；不预设发布日期，也不预先声明某个版本要包含哪些能力。具体发布限制见 [构建与发布](构建与发布.md#ci-产物与-release)。
- **不把未验证的设想写成承诺。** 候选能力只有先完成准入验证、在 PRD 中确认行为后，才进入实施。
- **修复优先于功能推进。** 重复发送、数据损坏、后台失控和凭证泄漏等问题优先处理；出现严重缺陷时可用下一可用版本号发布修复，并相应调整主题内的推进顺序。
- **可靠性标准不因推进节奏降低。** 后台调度、发送安全、凭证保护、数据一致性和 Windows / Linux 基础兼容性的要求始终不低于已发布版本。
- **范围按使用价值调整。** 主题内的事项可以调整优先级，但不为凑数量添加新选项。

## 2. 持续推进的主题

以下主题不按版本排序，可按使用价值独立推进。每个主题内的具体待办见 [待办](待办.md)，范围较大时再在 PRD 中确认功能行为与验收标准。

### 桌面常驻体验

目标是降低长期后台运行的使用成本：

- 保持开机自启动、启动后隐藏、托盘恢复与显式退出在 Windows / Linux 上的行为一致，并完成实机验收。
- 对登录失效或其他需要用户干预的情况提供恰当的额外提醒（如平台允许的系统通知）。
- 错误提示与实际原因一致，可直接指导用户操作。

### 日常使用完善

目标是让已有数据更容易使用与排查：

- 执行记录按任务、直播间、时间和状态筛选。
- 诊断日志查看、级别设置与手动清理；清理不得影响 SQLite 执行历史。
- 界面语言切换与更清楚的错误说明，按实际使用价值决定是否纳入。

本主题保持低风险维护：筛选与日志功能不得泄漏凭证，清理操作不得误删任务配置。

### 任务管理能力

在应用可靠运行并收到真实使用反馈后，从下列候选中选择：

- 任务模板、分组和常用配置复用。
- 任务导入 / 导出、配置备份与恢复。
- 执行统计及更清晰的历史分析。

**目前尚未形成这批能力的承诺交付清单**。决定实施时，先验证数据格式、版本兼容性、恢复失败处理和使用价值，再更新 PRD 及[相应待办](待办.md#4-任务管理能力)。

## 3. 长期方向

以下方向保留在候选池中，不预先指定版本号，以免把可行性尚未验证的设想变成承诺。

| 方向 | 候选能力 | 进入实施前需要验证 |
| --- | --- | --- |
| 高级调度 | 日期排除、节假日计划、有限 Cron 表达式、可控时间偏移 | 现有计划、时区、夏令时与防重语义已稳定 |
| 直播间后台持续刷新 | 已保存直播间信息的后台自动刷新 | 明确刷新范围与频率，避免接口集中请求；展示信息刷新不影响任务调度 |
| 任务编辑预览 | 编辑任务时预览执行计划 | 与实际调度使用一致的时区和计划语义，明确预览范围 |
| 直播间事件 | 开播触发、下播停止、指定直播间事件响应 | 事件来源合法可靠、断线恢复正确，不导致重复发送 |
| 账号扩展 | 多账号任务管理 | 安全存储、账号隔离、限流和失效处理能够正确演进 |
| 浏览器插件同步 | 首期 Chrome 扩展读取选定 Cookie Store 中的两个 Cookie，经配对的本地通道交给 Go | 用户主动安装、授权并配对，首次导入与重新授权由用户触发；扩展只获得 B 站所需权限，不读取 / 传播 `refresh_token`，由浏览器负责续期；任一时刻仅有一个生效的凭证来源，切换前停止旧来源的同步或续期；Go 验证 UID，账号切换时暂停覆盖并请求确认，失败不能静默丢弃有效凭证；仅在扩展运行、授权和本地连接均正常时持续同步；验证 Native Messaging 身份与消息边界、Cookie 删除再写入、Profile 切换、退出登录、连接中断及 Windows / Linux 双平台安装，不重新引入手动 Cookie 输入 |
| 更多运行形态 | 独立 Go CLI、无界面后台运行 | 确有需求，并解决凭证解锁、生命周期、部署和状态查看问题 |

现阶段不为这些方向预建插件接口、多账号架构、持久化通用队列或无界面运行服务。

## 4. 不纳入规划的事项

- 云端同步、多设备协作、Web 管理后台及移动端远程控制。
- AI 自动生成弹幕、自动回复、自动跟车或热门弹幕识别发送。
- 通用插件系统、自动更新服务及其他缺乏明确需求的平台化能力。
- 验证码绕过、风控规避、频率限制绕过等能力（不予支持）。

无论方向如何演进，都应保持**本地优先、凭证安全、发送可控、遵守平台规则**。

## 5. 从主题到可用功能

开始一个主题或事项时，检查：

1. **上一个交付节点是否达到验收标准？** 重复发送、数据损坏、后台失控和凭证泄漏等问题优先处理。
2. **候选功能是否值得做？** 优先解决真实用户问题；不为凑数量添加新选项。
3. **Windows / Linux 与 B 站接口是否支持？** 明确平台差异、必要的降级和失败反馈。
4. **数据与维护成本是否可控？** 尽量避免不必要的迁移、额外后台服务或复杂抽象。

确认后在 PRD 中写明功能与验收标准，必要时更新技术选型，再拆到待办的实施单元；未被选中的候选留在本文。**Roadmap 管方向，PRD 管产品行为，待办管执行与提交。**
