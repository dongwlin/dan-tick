# dan-tick 产品需求文档

本文定义产品行为、功能边界与验收标准，不记录开发阶段和实施进度。

产品方向与候选能力见 [Roadmap](ROADMAP.md)，实施项见 [待办](待办.md)。下文标为“增强功能”的要求，在相应能力纳入实施范围后适用，不代表已经实现或承诺交付。技术选型与项目例外见 [技术栈选型](技术栈选型.md)，模块职责与开发约定见 [项目开发指南](../AGENTS.md)。

## 1. 产品定位

dan-tick 面向需要定时或重复发送 B 站直播弹幕的个人用户，是运行在 Windows / Linux 上的本地桌面应用。用户通过图形界面管理直播间、任务和执行记录，设置完成后可保持应用在后台运行，无需打开浏览器或直播间网页。

产品优先保证定时可靠、发送可控、状态准确、凭证安全和低资源占用。任务与执行状态保存在本机，核心功能不依赖自建云服务；按单用户使用设计，不涉及多用户协作或商业化场景。

## 2. 目标用户与使用场景

| 场景 | 用户配置或操作 | 预期结果 |
| --- | --- | --- |
| 每天定时发送 | 向指定直播间创建每天 22:00 发送“晚上好”的任务并启用 | 应用运行时按计划自动发送 |
| 定时启动循环发送 | 每天 22:00 开始，三条消息顺序循环，间隔 15 秒，持续 5 分钟 | 队列循环发送，达到时长后停止并记录结果 |
| 立即执行 | 直接测试发送一条弹幕，或立即执行已保存任务 | 启动独立执行，不修改已有定时计划 |
| 后台运行 | 设置任务后隐藏主窗口 | 后台继续调度，用户能够恢复窗口 |
| 跨平台使用 | 在 Windows 或 Linux 上运行 | 核心任务逻辑、配置格式与操作流程保持一致 |

## 3. 功能需求

### 3.1 B 站账号管理

#### FR-001：账号凭证配置

当前仅管理一个 B 站账号，通过应用内扫码建立独立登录会话，不提供手动填写 Cookie 或账号密码登录入口。

账号设置提供扫码登录、重新扫码、登录状态检查和清除凭证。用户用 B 站手机 App 扫码并确认；扫码取消、超时或失败时有明确反馈及重新扫码入口。重启后可继续使用已保存且仍有效的会话，无需每次登录。

#### FR-002：登录状态检测

登录状态至少区分未配置、验证中、已登录、已过期和验证失败。网络或接口检查失败不能直接判为凭证过期；应先判断会话是否可安全续期。

确认无法续期、必须重新登录时：

1. 停止需要有效凭证的发送，并将对应任务执行标记为失败。
2. 提示用户重新扫码，不无限重试。
3. 保留任务配置。

验证成功后，设置页在凭证卡片上方展示头像、昵称和 UID，侧栏底部仅显示头像。头像不可用时回退默认用户图标；未登录或验证失败时不展示历史账号资料。展示资料来自登录检查结果，不包含 Cookie。

#### FR-003：凭证安全

凭证只保存到操作系统安全存储。Windows 使用系统凭证管理能力，Linux 使用 Secret Service 等机制；不可用时明确失败，不降级为普通配置文件中的明文存储。前端不长期持有完整凭证，所有鉴权请求由后端完成，日志不得记录凭证。

扫码会话的 `SESSDATA`、`bili_jct` 和 `refresh_token` 作为整组保存与轮换：

- 会话必须由应用独立创建，不使用从浏览器复制的刷新令牌自行续期。
- 替换凭证时核对 UID；与当前绑定账号不一致时请求用户确认，不静默覆盖账号或丢弃现有有效凭证。
- 续期与发送并发时，不能使用混合的新旧凭证。服务端刷新成功但本地保存或确认失败、会话无法恢复时，停止发送并提示重新扫码。
- 登录状态检查与续期分别处理；无法确认状态时明确反馈，遵守 FR-002 的失效处理规则，不承诺会话永久有效。

旧双字段 Keyring 凭证保留并明确提示需要重新扫码；重新绑定前拒绝发送，不静默删除凭证或影响已有任务。扫码及续期协议、字段与验证依据见 [B 站 API 对接参考](B%20站%20API%20对接参考.md#13-扫码登录与续期)。

### 3.2 直播间管理

#### FR-004：添加直播间

支持输入直播间 ID 或粘贴 B 站直播间链接，解析并验证目标直播间。保存的信息至少包括直播间 ID、标题、主播名称和用户备注，其中 ID 为必填字段。

#### FR-005：直播间信息展示

列表展示主播名称或备注、直播间 ID、标题及关联任务数量。接口支持时可展示直播状态，但直播状态仅为辅助信息，不作为调度的强依赖。

首次添加时必须完成必要解析与校验；直播间元数据字段与解析约定见 [B 站 API 对接参考](B%20站%20API%20对接参考.md#1-当前接口协议)。

#### FR-006：直播间管理

支持添加直播间、编辑备注、删除、查看关联任务和在浏览器中打开直播间。

删除直播间时处理关联任务并告知影响范围，可采用二次确认后级联删除。数据一致性要求见第 6 节，具体删除与历史关联策略见 [数据持久化设计](数据持久化设计.md#5-删除与历史清理)。

### 3.3 弹幕任务管理

#### FR-007：创建任务

每个任务具有以下属性，修改一个任务不影响其他任务：

| 属性 | 说明 |
| --- | --- |
| ID | 唯一标识 |
| 名称 | 用户自定义名称 |
| 直播间 | 目标直播间 |
| 任务类型 | 单次发送或循环发送 |
| 弹幕内容 | 一条或多条消息 |
| 执行计划 | 触发规则 |
| 启用状态 | 是否允许自动执行 |
| 运行状态 | 当前执行情况 |
| 创建时间、修改时间 | 配置的创建与最近修改时间 |

#### FR-008：任务类型

- **单次发送**：触发后发送一条指定弹幕，本次执行随之结束。
- **循环发送**：一条内容重复发送，或多条内容按顺序循环；支持固定间隔、最大发送次数和最大运行时长。

循环任务必须具有 FR-011 规定的停止条件，不提供默认无限循环模式。

#### FR-009：弹幕内容编辑

支持添加、删除、编辑、排序多条弹幕及预览发送队列。自动过滤空内容，按平台限制检查长度和内容格式；超出限制时提示修改，不静默截断。

当前沿用官方网页的加权计量方式，以 80 单位作为本应用固定上限，允许离线编辑任务；实际发送仍受账号 / 房间的平台额度约束。具体计量、提交校验和核验边界见 [B 站 API 对接参考](B%20站%20API%20对接参考.md#12-发送直播弹幕)。

#### FR-010：发送间隔

循环任务按秒配置相邻消息间隔，默认值建议为 15 秒。最短间隔结合接口行为和平台规则确定，并受 FR-019 的账号级限流约束；接口返回频率限制时停止或暂停发送。

#### FR-011：停止条件

循环任务必须配置发送次数或运行时长；两者同时配置时，任一条件满足即停止。用户手动停止或发生需要终止的错误也结束本次执行，取消规则见 FR-025。

#### FR-012：任务启用和禁用

启用允许未来计划自动执行，禁用阻止后续计划启动。禁用正在运行的任务时，明确提示是否同时停止当前执行。

### 3.4 定时调度

#### FR-013：定时任务类型

支持以下计划：

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 一次性 | 指定日期和时间执行一次 | 2026-10-15 22:00 |
| 每日 | 每天指定时间执行 | 每天 22:00 |
| 每周 | 指定星期和时间执行 | 每周一、三、五 22:00 |

#### FR-014：时区支持

每个任务保存明确时区，默认 `Asia/Shanghai`，允许用户修改。按任务时区计算计划，正确处理夏令时和跨日期；操作系统时区变化不得改变已有任务的预期执行时间。

调度计算由后端负责，前端配置和展示结果。

#### FR-015：任务自动执行

应用运行、任务启用、到达计划时间、无执行冲突且账号凭证满足发送要求时，自动执行任务。窗口可见性不影响执行，后台行为见 FR-027。

#### FR-016：下次执行时间

定时任务展示最近执行时间、结果和下一次计划时间。禁用任务不显示有效的下一次执行时间；一次性任务完成后显示已完成。

#### FR-017：避免重复执行

同一任务的同一计划实例仅允许自动启动一次，持久化必要执行标识与调度记录。以下情况均不得导致重复启动：

- 短时间重复触发
- 系统时间变化
- 睡眠恢复
- 窗口重复打开
- 调度重新初始化
- 应用重启

手动执行作为独立实例处理，见 FR-024。

#### FR-018：错过执行时间

默认不补发错过的任务。应用恢复后记录“已错过”并重新计算未来计划，不能集中补发历史弹幕。

一次性任务错过后标记为“已错过”，不自动改期。应用不负责唤醒电脑；启动及睡眠恢复的处理顺序见第 7 节。

#### FR-019：任务冲突处理

不同任务可以同时待执行，同一任务不能产生多个并发自动执行实例。发送统一协调，同账号的所有任务、直播间及测试发送共享频率限制；争用发送能力时按调度触发顺序排队。

执行记录应体现排队与实际开始时间。

### 3.5 弹幕发送

#### FR-020：直接调用 B 站接口

弹幕由后端 HTTP 客户端直接发送，不依赖浏览器自动化、脚本或直播间网页。接口路径、参数与认证协议统一见 [B 站 API 对接参考](B%20站%20API%20对接参考.md)，不在本文重复维护。

第三方接口不保证长期稳定或永久允许本应用使用；接口变化、会话失效、平台限频、内容过滤和网络失败都需要明确处理。

#### FR-021：发送结果处理

至少识别成功、网络连接失败、超时、凭证无效、频率限制、接口拒绝、参数错误和未知错误。

HTTP 200 不能单独证明成功，必须检查业务响应。成功仅代表服务端接受请求，不保证弹幕对所有观众可见。

#### FR-022：发送超时与重试

HTTP 请求设置合理超时并支持取消，遵守以下规则：

1. 不无限重试；登录失效时不自动重试。
2. 频率限制遵守服务端限制。
3. 对明确未发送的临时失败，可以有限重试。
4. 结果不确定时默认不自动重试，避免重复弹幕。
5. 所有重试行为写入执行记录。

#### FR-023：立即发送测试

用户选择直播间、输入弹幕并点击发送后，执行真实请求并展示结果；失败时说明原因，不能只检测网络连通性。

测试发送遵守 FR-019 的限流规则。每次测试均写入执行历史并标记“测试发送”，明确失败和结果不确定也记录；不关联或修改任何任务及定时计划。

### 3.6 任务运行控制

#### FR-024：手动执行任务

每个任务提供“立即执行”：单次任务发送对应弹幕，循环任务按保存规则启动一次完整执行。手动执行是独立实例，不修改原定时计划或下一次计划时间。

#### FR-025：停止任务

用户能够主动停止运行中的任务。停止时立即取消后续待发送消息及可取消的网络请求，更新状态并记录停止时间和原因；已经完成的 HTTP 请求无法撤回。

#### FR-026：任务执行状态

执行实例至少区分等待执行、排队中、正在运行、已完成、已停止、已失败和已错过。任务启用状态与执行状态分别管理；已启用的每日任务可以没有正在运行的实例。

## 4. 桌面应用能力

### 4.1 后台运行

#### FR-027：关闭窗口时保持运行

支持隐藏主窗口后继续调度与发送，再次打开时恢复任务状态。用户能够区分隐藏与退出，关闭按钮行为可配置，默认优先隐藏到后台。

隐藏必须有可靠的窗口恢复入口；系统托盘不可用时也不能使窗口无法找回。

### 4.2 系统托盘

#### FR-028：托盘菜单

在平台支持时尽可能提供托盘，菜单至少包含打开主窗口、查看运行状态、暂停自动调度、恢复自动调度和退出。

Linux 考虑不同桌面环境的托盘支持差异；无法显示托盘时提供可靠的备用操作方式。

### 4.3 开机自启动

#### FR-029：开机自启动设置

开机自启动为增强功能，纳入实施范围后满足以下要求：

1. 默认关闭，在设置中启用或禁用。
2. 在用户登录桌面会话后启动，Windows / Linux 均支持。
3. 支持启动后隐藏，但须满足 FR-027 的窗口恢复条件。
4. 关闭时清理此前创建的启动项。

自启动不表示系统未登录时执行，应用不要求在无图形用户会话下运行。

### 4.4 应用退出

#### FR-030：退出确认

有已启用的定时任务或正在运行的任务时，退出前提示：任务将在应用退出后停止，直到再次启动。

退出时停止自动调度、取消待执行请求、持久化状态并释放系统资源。

### 4.5 单实例运行

#### FR-031：防止重复启动

同一用户会话默认只运行一个实例。重复启动优先激活已有窗口，不创建第二个调度器或重复启动任务。

## 5. 图形界面需求

### 5.1 窗口布局与列表加载

- 窗口最小尺寸为 **1080 × 680**（逻辑像素），默认 **1280 × 760**；启动不超出系统可用工作区。Windows / Linux 均需验证最小尺寸、系统缩放和内容可访问性。
- 在不小于最小尺寸的窗口中，整体页面不产生横向或纵向滚动条，标题、主要操作和导航保持可见。
- 超出空间的列表、设置分组或编辑表单等明确容器可独立滚动；不得用裁切隐藏功能。长文本采用截断、换行或详情入口。
- 总览仅展示有限摘要，不分页；“最近执行”随窗口高度展示 **2～5 条**，其余由“全部记录”访问。“全部任务”进入完整任务页；即将执行及异常卡片可内部滚动。最近执行表头固定，仅数据内容区滚动。

列表加载规则：

| 列表 | 加载与交互规则 |
| --- | --- |
| 执行记录 | 页码分页，按窗口可用高度计算完整数据行容量；结果不足或等于一页时隐藏分页。超出一页时，底部固定上一页、当前页码、下一页及记录范围与总数。翻页不滚动整体页面；末页不足以铺满时显示末条分割线和结束提示。筛选后回第一页，展开详情仅记录内容区局部滚动 |
| 任务与直播间（卡片 / 列表） | 按稳定顺序使用游标增量加载，内容区触底继续获取，必要时提供“加载更多”。有更多数据时不显示页码，加载完成且内容较少时显示分割线和“已全部显示”。搜索、筛选或排序变化后重置游标和已加载结果，避免重复和遗漏 |

分页字段约定见 [通用分页规范](specs/standards/backend/HTTP%20API%20设计规范.md)，本文只定义用户可见行为。

### 5.2 首页 / 仪表盘

展示账号状态、后台运行状态、启用任务数量、正在运行的任务、下一个即将执行的任务和最近执行记录，使用户能判断自动发送是否正常。

### 5.3 任务列表

展示任务名称、直播间、类型、调度规则、下次执行和启用 / 执行状态。提供新建、编辑、启用 / 禁用、立即执行、停止、删除和查看记录操作；各操作行为以第 3 节为准。

### 5.4 任务编辑界面

按以下三组组织配置，字段校验与执行规则以 FR-007～FR-014 为准：

| 分组 | 配置内容 |
| --- | --- |
| 基本信息 | 名称、直播间、类型、启用状态 |
| 弹幕设置 | 内容及排序、发送间隔、最大次数、最大时长 |
| 调度设置 | 一次性 / 每日 / 每周、日期、时间、星期、时区 |

执行预览为增强功能，纳入实施范围后展示下一次执行时间、预计最大发送数量和最长运行时间；已保存任务的下一次计划时间仍按 FR-016 展示。

### 5.5 执行记录界面

记录至少包含任务名称、计划时间、实际开始与结束时间、成功 / 失败发送数量、最终结果及错误说明，并可查看单次执行详情。加载规则统一见 5.1。

按任务、直播间、时间范围和执行状态筛选为增强功能。

### 5.6 设置界面

| 分组 | 内容与需求来源 |
| --- | --- |
| 账号 | 扫码、重新扫码、状态检查及清除凭证，见 FR-001～FR-003 |
| 应用 | 关闭窗口行为，见 FR-027；自启动及启动后隐藏为增强功能，见 FR-029；语言切换为增强功能 |
| 调度 | 默认时区；暂停 / 恢复全部自动调度 |
| 数据与日志 | 打开数据目录、打开日志目录及主动导出安全诊断包，见第 6 节；日志查看和手动清理为增强功能 |

## 6. 数据存储需求

### 6.1 本地存储与凭证隔离

本地持久化直播间、任务定义、弹幕内容、调度规则、启用状态、执行记录、最近调度信息及应用设置，支持重启后恢复。

普通数据与凭证隔离，敏感认证信息按 FR-003 管理，不进入普通配置。实体职责、持久化一致性与迁移规则见 [数据持久化设计](数据持久化设计.md)。

### 6.2 数据位置

使用系统推荐的用户数据目录，不默认写入桌面、安装目录、当前工作目录或临时目录。设置页提供“打开数据目录”。

诊断日志目录与数据库独立，设置页提供“打开日志目录”，调用系统文件管理器；目录为空也可打开，失败时明确提示。具体路径见 [README 的诊断日志说明](../README.md#诊断日志)。

### 6.3 数据一致性

1. 异常退出不能损坏全部配置。
2. 删除任务同步处理关联数据；修改保留唯一标识。
3. 历史能够正确关联原任务。
4. 损坏数据读取失败时明确报错，不静默覆盖全部数据。

### 6.4 执行历史与诊断日志

执行历史默认保留最近 **30 天**并自动清理，手动清理为增强功能，不取消默认保留策略。

本地结构化诊断日志默认开启，级别为 `info`，独立于执行历史；启动及数据库初始化失败也尽可能留下信息。日志按大小、数量和时间限制自动轮转、清理，具体参数统一见 [README 的诊断日志说明](../README.md#诊断日志)。日志不可写时不阻断核心业务，但提供可观察的降级反馈。

只记录必要时间、组件、事件、非敏感标识、结果类别及耗时。禁止记录凭证、Keyring 内容、弹幕正文、HTTP 请求体、原始上游响应或可能包含敏感信息的底层错误。

用户可主动导出经过敏感信息检查的诊断包，包含必要版本 / 平台信息及限定范围日志，不默认包含数据库或执行历史，不自动上传。诊断日志查看、手动清理历史与日志为增强功能。

## 7. 调度与运行可靠性

### 7.1 后台独立运行

调度及任务执行独立于前端界面，前端关闭、刷新或重建不得重复启动任务。模块职责与生命周期实现约定见 [后端开发指南](../internal/AGENTS.md)，本节只维护恢复与异常处理行为。

### 7.2 启动恢复

启动时加载持久化任务，检查未正常结束的执行记录，将上次异常中断的执行标为中断，再重新计算启用任务的下一次计划并恢复调度。

默认不恢复未完成的循环发送进度，错过的计划按 FR-018 处理。

### 7.3 系统睡眠

睡眠期间不保证按时执行。恢复后重新读取时间，按 FR-017 防重、FR-018 标记错过并重新计算未来计划，继续等待下一次执行。

不要求阻止系统睡眠或主动唤醒电脑。

### 7.4 网络异常

发送断网时展示网络错误，按 FR-022 的规则处理重试，避免高频请求；达到失败条件时结束本次执行，不影响其他任务配置。

## 8. 非功能性需求

### NFR-001：跨平台

目标平台为 Windows 10 / 11 和 Linux，均为 x86_64。核心业务结果保持一致；系统托盘、自启动及窗口行为允许平台特定实现。

Linux 优先验证 Fedora GNOME 及常见 X11 / Wayland 桌面会话；发行版适配范围、运行依赖和分发方式统一见 [构建与发布](构建与发布.md#linux-appimage-运行依赖与兼容范围)。

### NFR-002：资源占用

后台空闲时保持低资源占用，不高频轮询时间、不持续刷新隐藏界面、不创建无必要的后台线程、不在没有发送任务时持续请求 B 站接口。

### NFR-003：响应性能

普通操作流畅，保存后立即更新列表，调度计算和网络请求不阻塞界面。正常情况下尽量将计划执行误差控制在 **1 秒以内**；这不是硬实时保证，实际发送时间受系统调度和网络延迟影响。

### NFR-004：错误处理

关键操作失败须明确反馈，避免静默发送失败、任务卡在运行中、登录失效后持续重试、错误后无限发送或失败显示为成功。

### NFR-005：可维护性

核心能力保持清晰职责与可验证的边界。技术选择、模块组织、通信方式及测试约定统一在 [技术栈选型](技术栈选型.md) 和各级 [开发指南](../AGENTS.md) 维护。

### NFR-006：安全性

凭证安全见 FR-003，日志与诊断包的内容边界见 6.4。输入必须校验，网络请求使用 HTTPS，对异常响应安全处理，不向第三方服务上传登录凭证。

自动发送遵守平台规则，不提供验证码、风控或频率限制绕过能力。

## 9. 产品边界

当前发送内容为普通文字弹幕，不包含表情包等特殊消息类型。账号登录范围见 FR-001，应用依赖图形用户会话，见 FR-029。

后续候选及当前不纳入规划的能力统一见 [Roadmap](ROADMAP.md#3-长期方向)，不在本文重复维护清单；未确定实施的候选不作为功能或验收承诺。

## 10. 验收标准

以下场景用于验收与后续回归，不记录逐次发布的检查结果。Windows / Linux 的桌面能力需分别实机验证；自动测试使用模拟接口和假凭证，不访问真实 B 站生产接口。

### AC-001：账号配置

未配置账号的用户打开扫码登录，用 B 站手机 App 扫码并确认后，应用安全保存独立会话凭证并显示状态；重启可继续使用尚有效的会话。

扫码取消、二维码过期、网络失败及登录被拒绝有明确反馈和重试入口。设置页不出现手动填写 Cookie 的入口，见 FR-001。

### AC-002：单条弹幕发送

用户已登录且直播间有效时，点击立即发送会执行真实请求并显示实际结果。

### AC-003：多条循环发送

配置三条弹幕、15 秒间隔及明确停止条件后，执行时按顺序发送，达到停止条件后结束。

### AC-004：每日定时任务

每天 22:00 的已启用任务，在应用正常运行且时间到达时自动触发，无需打开直播间网页。

### AC-005：窗口隐藏

启用定时任务后隐藏主窗口，后台调度继续正常运行。

### AC-006：系统睡眠

任务计划在 22:00 执行，系统从 21:50 睡眠至 23:00 后，恢复时不自动补发。

### AC-007：防止重复执行

任务已完成当天自动执行后，系统时间变化或调度重新初始化不得再次执行同一计划实例。

### AC-008：登录失效

扫码会话经续期检查确认无法恢复时，尝试发送须停止并记录认证错误，提示重新扫码，不无限重试或清除任务配置。

### AC-009：任务持久化

创建多个任务后退出并重启，配置、启用状态及历史记录正确恢复。

### AC-010：跨平台

Windows / Linux 分别验证启动、账号配置、直播间添加、任务创建、定时发送、循环发送、手动停止、后台运行、退出与重启，核心业务结果一致。

### AC-011：并发与频率限制

两个任务同时触发并使用同一账号时，正确协调发送顺序，遵守统一频率限制。

### AC-012：异常处理

发送时遇到网络超时、接口错误或认证失效，正确结束或暂停本次执行，在记录中保留可理解的错误说明。

### AC-013：扫码会话自动续期

扫码独立会话需要续期时，在不中断正常授权的前提下安全轮换整组 Cookie 与 `refresh_token`，重启仍能使用新凭证。

服务端刷新成功但本地保存或确认失败、与发送并发或会话无法续期时，不能混用新旧凭证或无限重试，提供安全重新扫码入口。Windows / Linux 分别人工核验关键行为。
