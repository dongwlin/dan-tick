# 前端测试规范

## 1. 适用范围

本规范定义 Web SPA 的公共测试策略与质量边界，适用于 React 与 Vue 项目。

- 共享测试工具版本由前端技术 Profile 定义，框架专属测试约定由对应框架 Profile 定义。
- 交互与可访问性验收见《[[前端交互与可访问性规范]]》。

本规范规定“测试什么、在哪一层测试、如何保持可信”，不重复框架 API 教程。

## 2. 核心原则

### 2.1 测试用户可观察的行为

测试优先验证：

- 用户看到什么；
- 用户可以执行什么操作；
- 操作后界面如何变化；
- 请求成功或失败后得到什么反馈；
- 模块通过公开契约暴露什么结果。

不要把内部 state、私有方法、Hook / Composable 调用次数和组件树结构当成主要断言。

### 2.2 选择最低成本且足够可信的层级

能用纯函数单元测试证明的规则，不挂载组件；需要 DOM 交互时使用组件测试；跨路由、状态管理和 HTTP 边界才使用页面集成测试；只有完整部署流程才使用 E2E。

| 层级 | 主要对象 | 默认可信边界 |
| --- | --- | --- |
| 单元测试 | 纯函数、Schema、状态转换 | 进程内 |
| 组件测试 | 表单、列表、弹层、复用组件 | DOM 行为 |
| Story 测试 | 可复用组件状态与交互 | 真实浏览器组件环境 |
| 页面集成测试 | Router、Query、Store、HTTP 状态组合 | 应用内集成 |
| 浏览器组件测试 | Focus、拖拽、布局、浏览器原生行为 | 真实浏览器 |
| E2E | 部署后的关键用户流程 | 完整系统入口 |

测试层级越高，数量默认越少。

### 2.3 测试是风险控制，不是文件配额

不要求每个组件、每个状态逻辑或每一行代码都有测试。优先覆盖错误后会造成业务损失、权限泄漏、数据错误或高回归成本的行为。

### 2.4 测试必须独立且可重复

- 任意测试可以单独运行；
- 不依赖执行顺序；
- 不访问真实公网服务；
- 不复用其他测试留下的 DOM、Store、Query Cache、Mock 或定时器；
- 时间、随机数、时区和浏览器存储影响结果时必须显式控制。

## 3. 测试优先级

### 3.1 P0：必须覆盖

- 认证恢复、退出和权限判断；
- 金额、数量、时间、状态流转等核心业务规则；
- 创建、修改、删除、提交等关键 Mutation；
- 表单必填、边界值和服务端字段错误；
- Loading、Empty、Error、Success 等关键页面状态；
- 乐观更新失败后的回滚；
- 已修复的生产缺陷与高风险回归。

### 3.2 P1：按风险覆盖

- 路由参数、查询参数和受保护路由；
- Query Key、缓存失效、分页和筛选；
- Store 状态转换与持久化恢复；
- 复杂可复用组件的键盘和交互；
- 防抖、节流、定时刷新和请求取消；
- 页面级错误边界。

### 3.3 P2：通常不单独测试

- 无条件分支的纯展示包装；
- 第三方库自身已经保证的行为；
- Tailwind Class 排列顺序；
- 私有变量与内部函数调用次数；
- 只为提高覆盖率而执行、没有有效断言的代码。

## 4. 文件组织与命名

测试默认与被测文件共置。跨多个 Feature 的页面集成测试与共享测试设施放在顶层 `tests/`。

统一使用 `.test.*`，同一项目禁止混用 `.spec.*`。

测试名必须描述场景与结果，禁止“works”“renders correctly”“test submit”等没有行为信息的名称。

一个测试表达一个业务行为，可以包含证明该行为所需的多个相关断言。

## 5. 元素查询与断言

### 5.1 查询优先级

DOM 测试按用户和无障碍树能够感知元素的方式查询：

1. Role + Accessible Name；
2. Label；
3. Placeholder；
4. 可见文本；
5. Test ID。

能通过语义角色、可访问名称或表单标签定位时，禁止新增 `data-testid`。

### 5.2 断言最终结果

优先断言：

- 用户可见文本和状态；
- 可见、可用、选中与可访问名称；
- 表单错误位置；
- URL、Focus 与页面状态；
- 对外公开回调 / emit 的数据。

不要仅断言“某内部函数被调用”，除非外部端口交互本身就是公开职责。

## 6. 用户交互与异步行为

- 交互测试使用真实用户语义，而不是直接触发内部事件处理函数；
- 异步测试等待用户可观察结果，不用任意 sleep；
- Fake Timer 只用于确实依赖时间的逻辑，并在测试后恢复；
- 测试不得依赖真实网络速度、机器时钟或执行顺序。

## 7. 测试替身与 HTTP Mock

### 7.1 Mock 外部边界

默认在系统边界替换依赖，不 Mock 被测实现内部。

HTTP 行为统一在网络边界使用 MSW。页面集成测试应让生产请求链路真实执行到 HTTP 边界，再由 MSW 返回符合《[[HTTP API 设计规范]]》的响应。

### 7.2 Module Mock 是最后手段

只有无法通过依赖注入、HTTP 边界、浏览器 API Fake 或公开契约稳定控制时，才使用 Module Mock。

禁止 Mock TanStack Query Hook、Router 内部状态或被测组件的私有子模块来制造“通过”。

### 7.3 清理

每个测试必须清理或重置：

- DOM；
- Query Cache；
- Store；
- MSW handler；
- Timer；
- 浏览器存储；
- 全局事件监听器。

## 8. Storybook

Storybook 负责可复用 UI 组件的：

- 代表性视觉状态；
- 交互示例；
- 可访问性检查；
- 边界状态与窄视口场景。

以下组件默认需要 Story：

- 共享基础 UI；
- 复杂业务复用组件；
- 有多种交互或视觉状态的组件。

Story 不是登录、跨页面写操作或真实后端协作的 E2E 替代品。

## 9. 页面集成测试

页面集成测试默认使用真实：

- Router；
- Query Client；
- Store；
- 生产 API Client；
- MSW HTTP 边界。

目标是验证页面编排与边界协作，而不是复制 E2E。

## 10. Browser Mode

只有行为确实依赖真实浏览器时才升级到 Browser Mode，例如：

- Focus；
- Pointer / Drag；
- Layout；
- CSS 与浏览器原生控件；
- jsdom 无法可靠模拟的 API。

普通业务逻辑和大多数 DOM 行为仍使用更快的测试层级。

## 11. E2E

Playwright E2E 只覆盖高价值完整流程，例如：

- 登录 / 会话恢复；
- 核心创建、编辑、提交流程；
- 权限或跨页面导航；
- 关键回归路径。

E2E 数量保持克制，不用它替代单元、组件和页面集成测试。

## 12. Snapshot

Snapshot 只适合稳定、结构性输出。禁止用大面积 DOM Snapshot 代替行为断言。

Snapshot 更新必须能解释为什么输出变化，而不是看到失败就批量接受。

## 13. 覆盖率

覆盖率是发现遗漏的信号，不是质量目标。

- 不以追求固定百分比为理由编写低价值测试；
- 关键业务规则和高风险分支必须实际覆盖；
- 新增或修改高风险逻辑时检查相关覆盖变化；
- 覆盖率阈值可以作为防止明显倒退的项目级门槛，但不能替代测试评审。

## 14. CI

合并前至少运行：

- 类型检查；
- Lint；
- 普通 Vitest；
- Storybook 测试项目；
- Storybook 静态构建；
- 生产构建。

E2E 在具备稳定部署环境的主分支、发布候选或合适的合并请求运行。

## 15. 开发工作流

修改公共行为时默认流程：

1. 先明确新的可观察行为；
2. 对缺失行为添加或更新测试；
3. 完成最小实现；
4. 在测试保护下重构；
5. 运行受影响测试与必要的更高层测试；
6. 检查最终 diff 是否引入无关测试和无意义 Mock。

修复可复现缺陷时必须添加能证明缺陷不会回归的测试，除非存在明确且记录的技术原因。

## 16. 速查清单

- [ ] 测试断言用户可观察行为。
- [ ] 使用最低成本且足够可信的层级。
- [ ] HTTP 在网络边界 Mock。
- [ ] 没有为了覆盖率制造低价值测试。
- [ ] 已修复缺陷有回归测试。
- [ ] 测试可独立、可重复运行。
