# Wails 服务与生命周期规范

## 1. 适用范围

本 Profile 规定 Wails 3 桌面应用中 Go Service、前端 Binding、Events 与应用生命周期的边界。它不规定业务调度算法、数据库 Schema 或窗口具体视觉方案。

## 2. Service 与 Binding

- Go Service 作为前端访问后端用例的入口，公开方法只暴露页面所需的操作和数据，不把 Bun 数据库对象或系统凭证作为返回值。
- 通过 Wails 自动生成的 TypeScript Binding 调用后端；禁止手写第二套 HTTP / RPC API 来重复相同能力。
- Binding 方法负责参数边界、调用业务能力与转换结果，不在其中实现调度循环、SQL 查询或平台凭证细节。
- Wails 自动生成的 Binding 文件只能由生成流程更新，不手动修改。
- 公开错误提供可识别的业务类别与安全展示信息；不得把内部堆栈、秘密或未经处理的第三方响应直接返回前端。

## 3. Events

- Go 向前端主动推送状态变化时使用 Wails Events；前端用户发起的查询和操作使用 Binding，不用事件代替方法调用。
- Event 表示已经发生的变化或需要刷新的通知，持久化业务事实仍由 Go 持有。前端收到通知后按需重新读取，不以 Event 流代替数据库。
- 注册稳定、精简的事件名称和数据结构；订阅在界面相应生命周期结束时解除，避免重复监听。

## 4. 生命周期与后台运行

- 应用组合根明确管理 SQLite、调度器、HTTP Client 和平台能力的初始化及关闭。需要启动和停止的组件使用 Wails Service 生命周期或明确的应用钩子统一管理。
- 调度器在 Go 后端独立运行，不能依赖前端组件是否挂载、窗口是否显示或页面是否刷新。
- 隐藏窗口与退出应用是两个不同操作；后台任务是否继续运行取决于进程生命周期，而不是 WebView 状态。
- 正常退出时停止接收新任务、取消可取消的操作、收尾执行记录，再关闭数据库等资源。启动失败必须清晰返回错误，不启动半初始化的调度器。
- 系统睡眠与恢复事件只用于触发重新核对当前时间和任务状态；不能假定所有平台或桌面会话都会可靠发出该事件，恢复逻辑还需在调度边界校验。

## 5. 平台适配

- Windows 和 Linux 的托盘、窗口、开机自启动、Keyring 等能力通过明确的平台边界管理；共有业务层不得依赖平台特有实现。
- 不支持某项平台能力时必须提供明确反馈或经产品认可的降级行为；凭证安全存储不可静默降级。
- 不为了假设未来有多窗口或多进程而提前建立跨进程通信与分布式状态框架。
