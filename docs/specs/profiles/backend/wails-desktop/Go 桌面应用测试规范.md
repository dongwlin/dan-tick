# Go 桌面应用测试规范

## 1. 适用范围

本 Profile 规定 Go + Wails + SQLite 桌面后端的默认测试策略，关注调度时间、持久化、外部请求和平台能力；不使用 PostgreSQL Testcontainers 或 Gin Handler 测试作为默认模板。

## 2. 测试原则

- 优先验证公开行为、数据约束和业务风险，不断言私有实现细节；不为了提高覆盖率而添加无有效断言的测试。
- 使用 Go 标准库 `testing`，并用 testify 的 `require` / `assert`、`ErrorIs` / `ErrorAs` 表达断言。
- 测试独立运行，时间、时区、数据库、外部 HTTP 和运行时状态可控；禁止访问真实第三方生产接口或使用实际账号凭证。
- 不为了 Mock Bun 而建立生产 Repository 接口；需要隔离副作用时仅替换实际存在的外部能力边界。

## 3. 测试分层

| 对象 | 默认测试方式 | 核心验证 |
| --- | --- | --- |
| 纯业务规则 | 单元测试 | 参数、状态转换与错误语义 |
| 计划计算 | 可控时间的单元测试 | 时区、夏令时、一次性 / 周期计划的边界 |
| 调度器 + 持久化 | 真实 SQLite 集成测试 | 同一计划防重、超时错过、异常恢复、重新注册 |
| Bun 数据访问 | 临时 SQLite 数据库 | 迁移、外键、事务与模型映射 |
| 执行器 | 可控时钟及 HTTP / 发送边界替身 | 发送顺序、停止条件、取消、重试和结果不确定 |
| HTTP Client | `httptest` | 超时、业务状态码、鉴权失败、限流与响应解析 |
| Keyring / 桌面能力 | 单元测试 + 对应平台验证 | 不支持 / 锁定场景、清理和用户反馈 |

## 4. 实践与 CI

- 同类输入和边界优先使用表驱动测试；只测一个清晰行为时无需强制表格模板。
- 不使用真实长时间 `sleep` 等待定时任务来证明业务正确性；仅在验证调度库真实集成时做少量受控运行测试。
- 异常恢复要用关闭后重新打开真实 SQLite 数据库的方式检验持久化，不依赖进程内假数据。
- 运行 `go test ./...` 和 `go vet ./...`；并发敏感模块及支持的 CI 环境运行 `go test -race ./...`。
- Windows 和 Linux 的 WebView、托盘、睡眠恢复与 Keyring 行为需要实际平台验证；Go 单元测试通过不能替代这些验收。
