# Go 桌面调度规范

## 1. 适用范围

本 Profile 定义单进程桌面应用使用 `robfig/cron/v3` 时的调度与任务执行边界。适用于持久化周期任务、一次性任务和可能产生外部副作用的任务；具体任务种类、错过执行宽限、夏令时策略与频率限制数值由项目业务规范确定。

## 2. 调度库职责

- 使用 `robfig/cron/v3` 解析和触发周期计划，不再自行实现通用 Cron 解析器与轮询循环。一次性任务复用统一调度管理入口，执行后移除注册并持久化最终状态。
- 每项任务保存明确的 IANA 时区，解析时使用 `time.LoadLocation`；注册 Cron 时按任务时区设置，不依赖 `time.Local` 表示用户保存的时区。
- 业务层只提供已支持的调度类型，不因底层采用 Cron 就默认向用户暴露任意 Cron 表达式。
- 创建、修改、禁用或删除任务后更新相应 Cron 注册；避免遗留重复注册。停止应用时结束调度器并按业务规定收尾运行中的任务。
- Cron 回调只负责确认计划触发、登记执行实例并把任务交给执行器；不得在回调中直接实现外部 HTTP 发送循环。

## 3. 时间与持久化防重

- 自动执行实例使用稳定的「任务 ID + 计划触发时间」标识；开始运行前通过数据库唯一约束或等效原子事务登记。进程内锁、`SkipIfStillRunning` 等包装器不能替代持久化防重。
- 手动执行实例与计划实例区分，不能修改原定下一次计划时间。
- Cron 唤醒回调、应用启动和系统恢复后都必须根据真实当前时间检查计划实例是否仍允许执行；超出项目定义的允许迟到窗口时记录为错过，不补发历史批次。
- 计划时区固定于任务；系统时区变化不得静默更改已保存计划的语义。夏令时不存在的本地时刻、重复出现的本地时刻必须有项目级明确规则并纳入测试。
- Cron 的触发通知不是 durable queue；应用异常退出后应从持久化记录恢复状态，不能假设内存调度器保存了执行历史。

## 4. 执行器与外部副作用

- 执行器管理排队、发送间隔、停止条件、取消与执行记录；调度器不直接决定第三方请求的重试。
- 多任务共享同一账号或资源的限流能力；具体排队规则与限制数值由项目确定。不能以 `DelayIfStillRunning` 的单任务包装器代替跨任务的全局限流。
- 使用 `context.Context` 取消后续待执行步骤及可取消的网络请求；已发出的外部请求结果可能不确定，默认不盲目重试。
- 失败、取消、崩溃恢复和错过执行都必须形成可追踪的最终状态，避免长期停留在“运行中”。
