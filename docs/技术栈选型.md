# 技术栈选型

## 1. 定位与边界

dan-tick 是基于 Wails 3 的 Windows / Linux 本地桌面应用。本文只回答**用什么、为什么，以及项目相对通用规范的差异**。

产品行为与验收标准以 [PRD](PRD.md) 为准；后端包职责、数据访问、Binding 与生命周期契约见 [internal/AGENTS.md](../internal/AGENTS.md)；前端结构、交互与验证契约见 [frontend/AGENTS.md](../frontend/AGENTS.md)；实体、持久化一致性与迁移见 [数据持久化设计](数据持久化设计.md)；构建、打包与发布见 [构建与发布](构建与发布.md)。**本文不重复这些文档的内容。**

独立的 [UI 原型](../prototype/README.md) 使用 Vanilla TypeScript 和演示数据，不是正式 Vue 前端，也不作为正式前端的实现依据。选型按实际需要渐进引入，不为了符合技术栈清单预先搭建空模块；尚未使用的工具不预留抽象层。

## 2. 技术选型

| 领域 | 选型 | 约定 |
| --- | --- | --- |
| 桌面框架 | Wails 3 | Windows / Linux；应用生命周期与平台能力由 Go 管理 |
| 后端 | Go 1.25（当前 `go.mod`） | 业务逻辑、调度、持久化、凭证及 B 站 HTTP 请求 |
| ORM | Bun | SQLite 数据访问、模型映射和事务 |
| 本地数据库 | SQLite + `modernc.org/sqlite` | 使用纯 Go `database/sql` 驱动、Bun SQLite Dialect |
| 数据库迁移 | Bun Migrations | 版本化迁移，优先保持 SQL 和 Schema 清晰 |
| 日志 | zerolog | 结构化诊断日志，执行记录另存 SQLite |
| 调度 | `robfig/cron/v3` | 周期计划触发；可靠性由业务层和 SQLite 保障 |
| 凭证存储 | `go-keyring` | Windows Credential Manager / Linux Secret Service |
| HTTP 客户端 | `net/http` | Go 后端访问 B 站，显式处理超时与取消 |
| Go 测试 | `testing` + testify | 单元测试、真实 SQLite 集成测试、必要时 Race Detector |
| 前端 | Vue 3 + TypeScript | Composition API、`<script setup lang="ts">` |
| 构建 | Vite 8 | 沿用 Wails 的开发、构建和 Binding 生成流程 |
| 前端工具链 | Node.js 24.18.0 + pnpm 12.6.0 | 固定 Node / pnpm 版本，提交 `frontend/pnpm-lock.yaml`，安装使用 `--frozen-lockfile` |
| 前端静态检查 | ESLint Flat Config | JavaScript、TypeScript 类型感知、Vue 与 Vue 可访问性推荐规则，warning 视为失败 |
| 前端格式化 | Prettier | 独立运行；`eslint-config-prettier` 最后关闭 ESLint 冲突规则 |
| 页面路由 | Vue Router 4 | 使用 Hash History，集中维护路由表 |
| 样式 | Tailwind CSS v4 | CSS-first 配置；使用设计系统语义令牌 |
| 视觉设计 | 亚克力设计系统 | 浅色 / 深色主题、半透明材质、克制动效 |
| 交互组件 | Reka UI | 复杂交互使用成熟的无样式组件原语，由项目提供亚克力样式 |
| 图标 | `lucide-vue-next` | 统一图标包，保持一致的尺寸、线宽和无障碍标注 |
| 客户端状态 | Pinia 3 | 只管理实际需要跨组件共享的前端状态 |
| 异步数据 | `@tanstack/vue-query` 5 | Go 业务数据的查询、Mutation、缓存与失效；设置类状态开关用乐观更新，写入期间锁定，失败后重新读取 |
| 表单校验 | Zod 4 | 输入及外部数据边界校验，后端仍负责最终校验 |
| 复杂表单 | vee-validate 5 | 任务编辑等动态字段、条件字段和多字段错误管理 |
| 前端测试 | Vitest + Vue Testing Library | 默认使用行为测试，必要时升级为真实浏览器测试 |
| 前后端通信 | Wails Service Binding + Events | Binding 用于查询和操作，Events 用于后端主动通知 |

### 版本与配置约定

- **依赖版本固定**：`frontend/` 与 `prototype/` 分别管理依赖及锁文件，不合并为 workspace；正式前端的依赖解析结果由 `frontend/package.json` 与 `frontend/pnpm-lock.yaml` 固定，Go 模块版本以 `go.mod` 为准，本文不列举。前端安装使用 `pnpm install --frozen-lockfile`。
- **发布间隔限制**：`frontend/pnpm-workspace.yaml` 只承载正式前端单包的安装策略，启用 `engineStrict: true` 与 `minimumReleaseAge: 10080`（7 天），不为具体依赖组合设置例外。
- **升级义务**：新增或升级依赖时提交匹配的锁文件，并验证 Vue / TypeScript / Vite / Node 与 Wails 3 的组合，而不只是安装成功。实际验证使用更高版本的 Go，不代表变更 `go.mod` 的最低版本要求。
- **前端工具约定**：ESLint 使用 Flat Config，启用类型感知、Vue 与可访问性推荐规则并把 warning 视为失败；Prettier 独立运行，由 `eslint-config-prettier` 最后关闭冲突规则。`typecheck` 同时检查 Vue 源码与构建配置，`build` / `build:dev` 先执行该检查。源码与生成 Binding 分别使用 `@/*`、`@bindings/*` 别名，TypeScript / Vite / Vitest 同步解析。具体规则、脚本与忽略范围见 [frontend/AGENTS.md](../frontend/AGENTS.md)。
- **已知风险**：`lucide-vue-next` 有上游弃用提示，将来更改包名需同步评估选型。

### 构建与运行时分发

- **构建元数据**：版本号按构建场景从 Git HEAD 与正式 Tag 推导，本地开发固定为 `dev`；Commit 使用本次构建的 Git HEAD，构建时间在实际编译桌面可执行文件前记录为 UTC RFC 3339 时间。三项元数据经 `-ldflags -X` 注入 `internal/buildinfo`，不使用 `debug.ReadBuildInfo()`；界面通过 `ApplicationService.GetBuildInfo` 读取，缺失时显示缺省值，不用启动时间或文件时间冒充。
- **Linux 分发**：采用薄 AppImage + 系统 WebKit，以 Ubuntu 24.04 为编译基线，GTK4 / WebKitGTK / 沙箱工具等运行依赖由发行版提供；应用不收集系统动态库、不设置 setuid、不通过关闭沙箱绕过平台限制。
- **开机自启动**：Go 直接管理当前用户的启动项，以稳定应用 ID 读取、更新与删除，不在 SQLite 另存启用状态。Windows 使用 [HKCU Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)，Linux 使用 [XDG Autostart](https://specifications.freedesktop.org/autostart/latest/)；AppImage 优先使用 [`APPIMAGE` 原始文件路径](https://docs.appimage.org/packaging-guide/environment-variables.html)，避免注册临时挂载内的可执行文件。当前 Wails 实现以可执行路径识别启动项，无法满足移动后的稳定清理与 AppImage 路径要求，因此使用项目内的平台适配。该开关默认关闭，关闭时删除本应用创建的启动项。
- **启动后隐藏**：启动可见性作为非敏感偏好保存于 `app_settings`，启动时读取一次，并以 Wails 的窗口 `Hidden` 选项创建主窗口，避免先显示再隐藏。隐藏窗口仍加载前端，调度与托盘保持可用；窗口恢复入口为系统托盘和再次启动可执行文件，因此不以托盘可用性作为启用前提。当前运行的窗口可见性由启动时的取值决定，界面修改在下次启动生效。

完整的版本规则、发行版矩阵、打包工具、运行依赖与发布流程见 [构建与发布](构建与发布.md)。

## 3. 通用 specs 的适用边界

已从 [specs 仓库](specs/spec-pack-manifest.json)引入 [Vue SPA Pack](specs/packs/Vue%20SPA%20Pack.md)，叠加 [亚克力设计 Pack](specs/packs/亚克力设计%20Pack.md)，并引入 [Wails 桌面后端 Pack](specs/packs/Wails%20桌面后端%20Pack.md)。复制的规范保留上游原文，来源版本和哈希记录在 `docs/specs/spec-pack-manifest.json`。

通用规范中与桌面应用相容的原则默认遵守。以下是 dan-tick 的**明确项目级取舍**，以本文为准：

| 上游约定 | dan-tick 的处理方式 |
| --- | --- |
| SPA 通过 `fetch` / HTTP Client 访问服务端，配套 HTTP API、Orval / OpenAPI、MSW | **不适用于 Wails 本地业务调用**，统一使用 Binding；B 站 HTTP 通信封装在 Go 后端。引入的《HTTP API 设计规范》仅作为上游引用闭包，不强制实现应用内 HTTP API。 |
| Vue Router 4 与基于 URL 的页面状态 | **采用 Vue Router 4 的 Hash History**，只用作桌面应用内部页面导航，不要求所有临时 UI 状态进入 URL；桌面路由不代表支持操作系统级外部深链。 |
| Pinia、表单库、Storybook、E2E 等完整 SPA 基础设施 | Pinia Store 按需创建；任务编辑表单采用 vee-validate + Zod，简单表单不强制使用；Storybook 与 Playwright 按实际需求引入，测试优先覆盖关键业务行为。 |
| 亚克力通过 CSS 背景模糊实现 | 用于应用内部界面；与操作系统桌面的原生透明 / 模糊效果单独评估，平台不支持时使用清晰可读的实心背景回退。 |
| Go API Pack 的 Gin、PostgreSQL、PASETO、HTTP Handler 与测试策略 | **不采用 Go API Pack**；后端以 Wails 桌面后端 Pack 为准，使用 Bun + SQLite、Keyring、Cron 和真实 SQLite 测试。 |
| [PRD](PRD.md) FR-028 的托盘菜单“至少包含……暂停自动调度、恢复自动调度” | **暂停与恢复合并为一个互斥条目**：调度开启时显示「暂停自动调度」，暂停时显示「恢复自动调度」，菜单同时只出现一个。条目在每次开关提交后按需读取 `app_settings` 刷新，不缓存状态也不定时轮询；Wails `v3.0.0-beta.25` 未暴露“菜单即将打开”的钩子，因此前端设置页写入同一开关时由提交后的 Go 内部回调通知托盘，后台读取后在 UI 线程更新菜单；回调注册不进入 Binding。实现与人工验证项见 [`internal/desktop/tray.go`](../internal/desktop/tray.go) 和[托盘说明](../assets/branding/README.md)。 |

前端测试框架固定为 Vitest；不引入 Jest、Cypress、MSW（Wails Binding 不是 HTTP）或大面积 DOM Snapshot，也不做覆盖率竞赛，工具开始实际使用时再加入相应脚本与 CI 检查。Storybook 使用 `@storybook/vue3-vite`，仅在开始维护一批可复用亚克力组件时引入。跨页面表单草稿的恢复策略在确有需要时单独设计，当前不做预设。

规范发生交叉或冲突时，业务范围以 `docs/PRD.md` 为准，**项目技术决策与上述例外以本文为准**；其余内容遵循 `docs/specs/` 中已引入的通用规范。未明确的技术方案保持待定，不从 Web SPA 模板推导为必须实现的功能。

## 4. 接入与维护

- 先阅读本文件，再按任务查阅 `docs/specs/packs/` 中的 Pack 及相关 Standard / Profile。
- 上游复制的规范不直接修改；项目差异记录在本文。需要同步上游规范时，使用 `specs` 仓库的 `tools/spec_pack.py copy` 更新，并以 `verify` 检查来源与本地漂移。
- 新增依赖、工具或抽象层时按实际需要渐进引入；独立 UI 原型的依赖与源码不代表正式前端的实现现状。
