# dan-tick 开发计划

## 1. 范围与执行原则

本文安排 **P0 最小可用桌面应用** 的实施顺序、提交单元与剩余验收。功能边界及验收标准以 [PRD](PRD.md) 为准，技术方案以 [技术栈选型](技术栈选型.md) 为准；数据库与外部接口分别参考 [SQLite Schema 与 Migration 设计](SQLite%20Schema%20与%20Migration%20设计.md) 和 [B 站 API 对接参考](B%20站%20API%20对接参考.md)。

- **以行为作为提交单位。** 每个单元包含可调用能力及必要验证，不提交空包、占位组件或未使用依赖；可独立验证的行为可以继续拆分，不可拆的改动一并提交。
- **保持构建基线可用。** Go 改动通过受影响测试；涉及 Wails / Binding / 正式前端时可重新生成 Binding 并构建。首版 SQLite Schema 整组迁移，后续已发布迁移只追加、不改写。
- **Go 是业务权威状态来源。** 正式 Vue 通过 Binding / Events 读取与刷新，不复制原型的 Vanilla TypeScript 业务状态，不另建本地 HTTP API。
- **自动测试使用替身。** 使用 `httptest`、临时 SQLite、可控时间和假 Keyring，不访问真实 B 站或使用真实凭证；真实账号操作与发送须另行获得用户明确授权，并遵守平台限制。

### B. 直播间和任务配置

| 单元 | 交付范围 | 验证要求 |

| [x] B3 | 实现任务创建与读取，保存有序消息列表并计算 `next_due_at` | 真实 SQLite 事务测试验证合法性、提交和回滚、重启后任务和消息仍在 |
| [x] B4 | 实现任务编辑、启用 / 禁用、逻辑删除；与关联直播间的有效性保持一致 | 真实 SQLite 测试验证编辑失败回滚、禁用后无有效待执行计划、删除后历史关联不丢失 |

直播间删除、任务编辑或删除遇到 `waiting` / `queued` / `running` 执行时返回冲突并回滚，先停止活跃执行、等待收尾后再重试；禁用任务只清理后续调度，不停止当前执行。恢复直播间不会自动恢复已删除任务，逻辑删除保留历史关联。

任务创建校验类型、消息、循环停止条件及计划规则，过滤空消息；启用时计算并保存 UTC 毫秒的 `next_due_at`，禁用时不保留有效游标。编辑未改变计划时保留原游标，修改计划或重新启用时计算未来时刻。平台实际允许的长度、发送间隔与真实发送行为仍需人工核对。

| 单元 | 交付范围 | 验证要求 |

| [x] C1 | 接入系统 Keyring 的写入、更新、清除和读取能力，并定义不可用时的错误反馈 | 使用替代的安全存储边界测试增删及失败；实际 Linux Secret Service / Windows Credential Manager 分别安排手动核对，绝不回退明文 |
| [x] C2 | 接入 B 站登录状态检测（读取 Keyring 凭证），返回可供界面使用的非敏感状态 | `httptest` 覆盖有效、失效、接口错误；日志、返回值均不得泄漏 Cookie |
| [x] C3 | 实现直播弹幕 HTTP 客户端，统一请求构造、超时、取消、业务响应判定与安全错误分类 | `httptest` 覆盖成功、鉴权失败、限流、超时及结果未知；HTTP 200 不等于成功，不确定结果不自动重发 |
| [x] C4 | 实现单账号共享发送限流入口，并使“测试发送”通过同一入口完成一次请求 | 模拟连续请求证明限流、取消和错误传播；测试发送返回真实客户端结果，并以 `test` 执行记录写入共享执行历史 |

C1 的旧双字段模型已由 H1 的版本化整组会话替代，凭证仍只存入系统 Keyring，不进入 SQLite、日志或普通前端状态，不降级为明文。账号检测与发送只返回非敏感状态和安全错误类别，不回显底层 HTTP 错误或上游原始响应。

手动、定时、循环及测试发送复用同一账号级 `Sender`。当前采用请求返回后至少等待 15 秒的保守默认值，**未经真实平台规则确认，不是官方最低间隔**；明确拒绝与未知结果均计入间隔，未实际发送或等待期间取消不消耗发送机会。限流错误不绕过、不自动重试；测试发送以 `trigger_kind = 'test'`、`task_id = NULL` 的实例写入同一执行历史，并保留任务名“测试发送”与直播间快照。

诊断日志使用 `zerolog`，默认 `info` 级别、JSON Lines，写入用户级日志目录；单文件最大 10 MiB、最多 5 个文件（含当前）、保留 14 天。轮转与清理不依赖数据库，不因日志故障阻断业务，降级反馈有界且可见。只记录预定义安全事件和允许字段，不写入弹幕正文、Cookie、请求 / 响应或任意底层错误文本。

### D. 手动执行与发送记录

| 单元 | 交付范围 | 验证要求 |
| --- | --- | --- |
| [x] D1 | 完成已有单条任务的手动执行：创建 `manual` 执行实例、请求前持久化 `pending`、回写结果和计数 | 临时 SQLite + 假 HTTP 测试证明手动执行不推进计划，成功 / 失败 / 未知结果均可追溯 |
| [x] D2 | 在同一执行链加入多消息循环、发送间隔、次数 / 时长停止条件及主动停止 | 可控时间与取消测试验证顺序、终止、未发送消息不继续执行；循环不允许无停止条件 |
| [x] D3 | 完成多任务争用同一账号发送能力的排队协调及同任务活跃执行冲突处理 | 并发测试验证账号级限流、排队顺序、运行状态和同任务不重叠；不引入持久化消息队列表 |

手动执行不推进计划，自动禁用的任务仍可手动运行；请求前先提交 `pending`，结果与计数事务化回写，持久化失败不继续发送。窗口导航或前端请求结束不取消 Go 持有的执行，主动停止与退出负责取消并等待收尾。

循环按保存的消息顺序发送，前一条返回后等待完整任务间隔；`max_count` 按逻辑消息尝试数计算，与 `max_duration_seconds` 同时配置时先到者结束，时长限制可取消进行中的请求。失败 / 未知结果不继续发送；无停止条件，或间隔 / 时长超出 Go `time.Duration` 范围时拒绝保存。账号 FIFO 顺序以请求进入共享 Sender 的时刻为准，不以任务登记时刻为准；HTTP 不放入数据库事务。

### E. 自动调度与恢复

| 单元 | 交付范围 | 验证要求 |
| --- | --- | --- |
| [x] E1 | 在 SQLite 事务中按 `task_id + scheduled_at` 原子领取计划、登记 `scheduled` 执行并推进 `next_due_at` | 同一计划重复触发只登记一次；同时运行冲突写为 `missed`；失败事务不产生半个执行实例 |
| [x] E2 | 接入 `robfig/cron/v3` 的计划注册、修改重注册、禁用移除及一次性任务触发 | 编辑后不会保留旧注册；回调只领取计划并交给执行器，不直接执行 HTTP；提交后的同步失败可报告和重建 |
| [x] E3 | 完成启动 / 睡眠恢复核对：错过判定、过期游标推进、遗留执行和 `pending` 结果收尾 | 测试覆盖 30 秒实时迟到边界及启动 / 唤醒不补发；关闭后重新打开 SQLite 验证不重复执行、不无限追溯历史，恢复后无虚假的运行中状态 |
| [x] E4 | 提供执行历史列表和单次执行详情查询 | 真实 SQLite 验证任务变更后历史快照、发送尝试顺序和错误显示所需字段 |
| [x] E5 | 实现默认保留 30 天执行历史的自动清理 | 真实 SQLite 验证只清理过期终态执行及其尝试，不清理仍在运行的执行和任务定义 |
| [x] E6 | 实现 P0 非敏感设置（如默认时区、调度总开关）的保存及恢复 | 重启后设置仍有效，暂停自动调度不会清除任务或影响已有历史；Keyring 不进入普通设置 |

- **计划身份与同步：** SQLite 的 `next_due_at` 是计划游标，Cron 只唤醒领取并交给共享执行器。提交后注册同步失败须明确已保存，可重建，不伪称数据库回滚；同任务活跃冲突记为 `missed/task_busy`。
- **迟到与恢复：** 实时 Cron 回调宽限 30 秒（含边界），超期记 `missed/schedule_overdue`；启动 / 显式唤醒恢复跳过已到期计划，即使不足 30 秒也不补发。长期离线至多记录一条代表性错过实例并推进未来游标。启动时遗留活跃执行标为 `interrupted`，其 `pending` 尝试标为 `unknown`；唤醒不终止本进程仍活跃的执行。
- **历史清理：** 启动及持续运行每 24 小时清理一次，仅删除 `finished_at` 严格早于滚动 `30 × 24h` 截止值的终态执行及关联尝试，不改任务定义、游标或活跃执行。清理失败安全记录并留待下次重试，不阻断应用。
- **普通设置：** 默认 `Asia/Shanghai`、自动调度开启；默认时区只影响未指定时区的新任务。总开关通过 Manager 保存并同步 Cron，暂停不改变逐任务启用标志、历史或已交接执行；恢复先按错过规则推进游标，不补发。凭证不进入普通设置。

### F. 正式前端工程与 Wails 集成

**设计基线：** 用户于 2026-10-11 确认 `prototype/` 六类页面，以 commit **`4bb1188`** 及 [原型说明](../prototype/README.md) 为布局与交互基线，以 [PRD 第 5 节](PRD.md#5-图形界面需求) 为功能验收依据。正式页面已完成集成，原型模拟数据不作为业务验收证据。

- 保持固定标题栏、侧栏、主题与信息层级；最小窗口 1080 × 680、默认 1280 × 760，主页面避免整体横纵滚动，内容容器按需局部滚动。
- 总览最近执行只滚动数据行、表头固定；执行记录按可用高度进行页码分页，单页隐藏分页，末页不足时显示结束提示；任务及直播间使用后端游标增量加载，条件变化时重置游标。
- 冻结后不因单纯视觉偏好重新设计；真实数据、可访问性、平台 WebView 或 PRD 与原型冲突时，先明确必要变更范围，再同步更新设计基线与相关文档。

#### G1. 窗口与后台运行检查

Windows、Linux 各用正常桌面用户会话验证，不使用真实账号发送：

1. 分别在有启用任务、无运行中任务两种状态下检查关闭主窗口：默认隐藏且后台计划继续；再次从系统启动器启动能找回同一窗口，不创建第二个调度器。
2. 从最小化状态重复启动，原窗口能显示并聚焦。
3. 将关闭行为切换为「退出」，分别用原生关闭、Alt+F4、标题栏「退出应用」检查警告：有启用任务或未结束执行时须确认，取消保持运行，确认停止执行并落库。
4. 重启后保留关闭偏好，无启用任务时能正常退出。
5. 无托盘宿主的 Linux 桌面仍可再次启动恢复窗口；原生确认框与窗口管理器行为须实测。

## 4. 单元如何执行与提交

执行编号前阅读对应需求、技术选型和相关 Pack，仅实现该单元所需行为。完成后：

1. **验证本单元：** 规则用对应 Go 测试；数据库用真实临时 SQLite，恢复场景重新打开；第三方 HTTP 用 `httptest`。原型在 `prototype/` 跑 `pnpm build`；正式 Vue 在 `frontend/` 跑 `pnpm run test`、`pnpm run lint`、`pnpm run format:check` 与包含类型检查的 `pnpm run build`。纯文档核对链接、路径和命令。
2. **确认集成边界：** Go 改动执行 `gofmt` 与受影响测试，并按需运行 `go test ./...`、`go vet ./...`、并发相关的 `go test -race ./...`。独立 Go 命令前需有 `frontend/dist/` 供 `go:embed` 使用，正式前端构建前需生成 Wails Binding；涉及桌面行为再运行 Wails 构建和平台人工验收。不能运行的检查记录原因，不视为通过。
3. **检查提交范围：** 执行 `git diff --check`、`git status --short`，不混入生成物、凭证或他人改动；使用英文 Conventional Commit，如 `feat(storage): add initial sqlite migrations`。不可拆的共同改动合为一个目的明确的提交，不留下依赖下一提交才能修复的状态。
4. **更新进度：** 通过对应验证才勾选；需求或依赖变化时同步条目及验收要求。实现完成与目标平台人工验收分别记录。
