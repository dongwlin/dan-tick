# dan-tick

dan-tick 是一款面向 Windows 和 Linux 的 B 站直播弹幕定时发送桌面应用。计划支持本地管理直播间、弹幕任务、定时调度与执行记录，由 Go 后端直接调用 B 站接口，不依赖打开直播间网页。

## 运行正式应用

需要 Go 1.25、Node.js 24.18.0、pnpm 12.6.0、Wails 3 CLI，以及目标平台所需的 Wails 构建依赖。

```sh
cd frontend
pnpm install --frozen-lockfile
cd ..
wails3 dev
```

构建当前平台的桌面应用：

```sh
wails3 build
```

## 开机自启动

设置页提供「开机自启动」，默认关闭。启用后，应用在当前用户登录桌面会话时启动并显示主窗口；关闭会删除本应用创建的启动项。设置页可重新读取启动项状态，启动项指向旧位置时可重新开启以更新路径，或直接清理。

Linux 使用用户配置目录中的 `autostart/io.github.dongwlin.dan-tick.desktop`（通常位于 `~/.config/`）；AppImage 注册原始文件路径并使用提取运行模式，无需 FUSE。移动应用或 AppImage 后，应在新位置重新开启自启动。Linux 自启动暂不支持路径包含 `%` 或 `=` 的应用，请将应用放在其他路径后启用。

Windows 使用当前用户的 `Run` 注册项。界面显示本应用的启动项注册状态；Windows「启动应用」或任务管理器中的禁用仍可能阻止应用启动，需要在那里重新启用。

开机自启动不负责在未登录桌面时运行，也不会唤醒电脑。启动后隐藏窗口是后续独立功能。

平台检查与尚待实机验收的范围见 [开机自启动验收记录](docs/开机自启动验收.md)。

## 诊断日志

正式应用启动时默认记录本地 JSON Lines 诊断日志，数据库初始化失败也会记录。活动文件为 `dan-tick.jsonl`；单文件最多 10 MiB，总共最多 5 个文件（含活动文件），轮转日志最多保留 14 天。日志与 SQLite 执行历史、Keyring 凭证相互独立。

- Linux：通常为 `~/.local/state/dan-tick/logs/`（可受 `XDG_STATE_HOME` 影响）。
- Windows：通常为 `%LOCALAPPDATA%\dan-tick\logs\`。

设置页提供「打开日志目录」和主动导出经过敏感信息检查的诊断包。日志不可写时不会阻止应用运行，界面可读取降级状态；日志与诊断导出的实机可操作性仍需对应平台验收。
